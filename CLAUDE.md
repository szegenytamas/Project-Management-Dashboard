# CLAUDE.md

Guidance for Claude Code (and any other AI assistant) working in this repository.
Read this before changing anything.

## Project

Project Management Dashboard: a JSON REST API to create, share and manage projects
and their documents. Exam project; the API contract is the table in `README.md` and
must not change without the mentor's agreement.

## Stack

- Python ≥ 3.12 (ships on 3.13), FastAPI, async everywhere
- PostgreSQL 17 via SQLAlchemy 2.x (async, `asyncpg`), migrations with Alembic
- Pydantic v2 for every request/response body, `pydantic-settings` for configuration
- Auth: argon2id (`pwdlib`), JWT HS256 (`PyJWT`), 1-hour tokens
- Tooling: `uv` (environment + lockfile), `tox` (+ `tox-uv`), `ruff`, `mypy --strict`, `pytest`
- Docker (multi-stage, non-root), Docker Compose for local dev, GitHub Actions CI
- Planned: AWS S3 + Lambda, RDS, EC2

## Layout

```
src/project_dashboard/
  api/routes/   HTTP only: status codes, response models
  api/deps.py   CurrentUser, require_project_access(action)
  schemas/      Pydantic models (input validation, output whitelists)
  services/     business logic; raises errors from services/errors.py, never HTTPException
  services/permissions.py   THE permission matrix - the only place roles are compared
  core/         config, security (hashing, JWT), error handlers
  db/           models, session, migrations/, schema.sql (same schema without ORM)
tests/          pytest; real PostgreSQL "<db>_test", one rolled-back transaction per test
```

## Rules

- **Git is done by the user.** Never run `git commit`, `git push` or `gh pr create`, and never
  add `Co-Authored-By` lines. Read-only git (`status`, `diff`, `log`) is fine. At the end of a
  phase, hand the user the commands, split into several meaningful commits.
- **Authorization** goes through `require_project_access(Action.X)` → `get_project_access()`.
  Non-members get 404, forbidden roles 403. Never compare roles anywhere else.
- **Every model change needs an Alembic migration**, autogenerated and then reviewed by hand.
  `tests/test_schema.py` fails if models, migrations and `schema.sql` disagree.
- **No secrets in the repo.** Settings without defaults (`POSTGRES_PASSWORD`, `JWT_SECRET_KEY`)
  come from `.env` (git-ignored) or the environment.
- **Never block the event loop**: CPU-heavy or synchronous work (argon2) runs in
  `run_in_threadpool`.
- **Use the database as the judge** for uniqueness (catch `IntegrityError`), not check-then-insert.
- Relationships are `lazy="raise"`: load them explicitly (`selectinload`), never rely on lazy loading.
- Tests assert behaviour (state in the database), not just status codes. Authorization changes
  need a row in `tests/test_authorization.py`.
- Before handing over: `uv run tox` must pass (lint, type, test) with no warnings.

## Commands

```bash
docker compose up -d db          # PostgreSQL on localhost:5433
uv run tox                       # everything CI runs
uv run alembic revision --autogenerate -m "..."
docker compose up --build        # full stack: db -> migrate -> api on :8000
```
