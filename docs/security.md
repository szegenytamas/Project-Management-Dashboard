# Security

How the service is protected, checked against the **OWASP API Security Top 10 (2023)**, plus
what is deliberately not done yet. Each row names the code or the test that proves it.

## OWASP API Security Top 10

| # | Risk | What we do | Proof |
|---|---|---|---|
| API1 | **Broken object level authorization** - reaching someone else's object by changing an id | Every project and document endpoint loads the object **joined with the caller's membership** in one query; no membership → **404**, so ids cannot be probed | `services/permissions.py`; `tests/test_authorization.py` (every endpoint × owner / participant / outsider, incl. database state) |
| API2 | **Broken authentication** | argon2id password hashes (in a thread pool); password policy (12-128 characters, four character classes, must not contain the login); JWT HS256 with a ≥ 32-character secret, algorithm pinned, `sub`/`iat`/`exp` required, 1-hour lifetime; same answer and timing for unknown login and wrong password; **rate limit** on `/auth` and `/login` (10 per minute per IP → 429 + `Retry-After`) | `core/security.py`, `schemas/auth.py`, `core/rate_limit.py`; `tests/test_auth.py`, `test_security.py`, `test_hardening.py` |
| API3 | **Broken object property level authorization** - reading or writing fields one should not | Responses go through **response models** that list the allowed fields (the password hash cannot leave); request models use `extra="forbid"`, so `total_size_bytes` or `role` cannot be sent in | `schemas/`; `tests/test_projects.py` (unknown fields rejected) |
| API4 | **Unrestricted resource consumption** | 10 MB per file (read limit + 1 bytes, never more), 10 files per upload, 50 MB per project under a row lock, password ≤ 128 characters (argon2 cost), ids bounded to BIGINT, login rate limit, DB connect timeout | `services/files.py`, `services/documents.py`, `api/deps.py`; document and hardening tests |
| API5 | **Broken function level authorization** - a participant calling owner-only functions | One permission matrix (`PERMISSIONS[role]`) for all actions; delete project, delete document and invite are owner-only → **403** | `services/permissions.py`; `tests/test_authorization.py`, `test_permissions.py` |
| API6 | **Unrestricted access to sensitive business flows** | The sensitive flows are account creation and login: rate limited. Invitations need an owner token | `core/rate_limit.py` |
| API7 | **Server-side request forgery** | The API never fetches a URL supplied by a client; S3 keys are generated by the server (`projects/{id}/{uuid}`) | `services/documents.py` |
| API8 | **Security misconfiguration** | Security headers on every response (`nosniff`, `DENY` framing, strict CSP, no referrer); no `Server` header; 422 errors without the submitted values; no stack traces to clients (503 for storage problems); non-root container; CORS **off** unless origins are listed explicitly; database TLS `verify-full`; S3 HTTPS-only bucket policy | `core/headers.py`, `core/errors.py`, `Dockerfile`; `tests/test_hardening.py`; CI smoke test checks the headers on the real image |
| API9 | **Improper inventory management** | One API version, documented in `README.md` and generated OpenAPI (`/docs`); every deployed image is traceable to its commit (`sha-<commit>` tag and OCI labels) | `.github/workflows/ci.yml` |
| API10 | **Unsafe consumption of APIs** | The only upstream API is S3 via boto3: errors become `StorageError` → 503 without internals; downloaded objects are streamed, not trusted as anything but bytes | `storage/s3.py` |

## Supply chain and secrets

| Control | Where |
|---|---|
| **Dependency scan**: every package in `uv.lock` (with hashes) is checked by `pip-audit` against the PyPI / OSV vulnerability databases on every pull request and merge; a finding stops the pipeline before build and deploy | CI job *Dependency and secret scan* |
| **Secret scan**: `gitleaks` scans the **whole git history** (a secret deleted later is still in old commits); the gitleaks binary is verified against its published checksum before it runs | same job |
| Exact versions everywhere: `uv.lock` for Python (also for the Lambda zip), pinned action versions, pinned base images and tool versions | `uv.lock`, `ci.yml`, `Dockerfile` |
| No secrets in the repository: required settings have no defaults; locally `.env` (git-ignored), in AWS **SSM Parameter Store** SecureStrings | `core/config.py`, `infra/aws/ec2/deploy.sh` |
| No long-lived AWS keys: EC2, Lambda and the CI deploy job use **IAM roles** (CI via GitHub OIDC) | `docs/aws.md` |

## Least privilege in AWS

| Identity | May do |
|---|---|
| EC2 instance role | Get / Put / Delete objects under `projects/`; read **two** SSM parameters (the app's DB password, the JWT key). The `dbadmin` and Lambda passwords, needed only for the one-time setup, were removed afterwards |
| Lambda role | List and delete under `projects/` (cannot read files); logs; VPC networking |
| CI deploy role | Run **one** SSM document (`deploy.sh` with a validated image tag) on **one** instance; only for this repository's `production` environment |
| Database user `size_lambda` | Three columns (column-level grants) |

## Not done (yet), and why

| Gap | Risk | Plan |
|---|---|---|
| **HTTPS** | Passwords and tokens cross the internet unencrypted | Needs a domain name: Caddy + Let's Encrypt on the server, or a load balancer + ACM certificate. Then add `Strict-Transport-Security` |
| Rate limit is per process and per IP | Several API instances would each count separately; users behind one NAT share the limit | A shared store (Redis) or AWS WAF rate rules once there is more than one instance |
| JWTs cannot be revoked before they expire | A stolen token works for up to an hour | Short lifetime limits the damage; refresh tokens or a deny-list as a next step |
| No pagination on `GET /projects` | A user with very many projects gets one large response | Pagination is a listed extension |
| Image vulnerability scan (OS packages) | The base image's Debian packages are not scanned | Trivy in CI |
